# Demo case selection without seeded identities

Prepared buyer/supplier identities, source identifiers and rehearsal observations are private evaluator material. They must not appear in public case documents, agent instructions, tool descriptions, fixtures used as live data, or the discovery service's inputs. No prepared candidate catalog is part of the application.

## Select and verify privately

1. Research one plausible buyer requirement and several relevant suppliers using live public sources. Then research a backup.
2. Inspect the buyer's mandatory specifications, standards, deadlines and applicable lots. A supplier's category page alone does not establish qualification.
3. Record original sources, exact quotations, individual retrieval timestamps, content hashes and unknowns in private evaluator notes.
4. Rehearse with a fresh discovery context and fresh retrieval. The request may describe the actual buyer need but must not name the desired supplier, supply its domain or refer to a previous shortlist.
5. If the intended supplier is not independently found and supported, revise the case openly. Do not add an identity exception or weaken a mandatory requirement to make it win.

## Separate public evidence from connected accounts

- Discovery and evidence ranking receive no participant directory, connection flag, account aliases or private rehearsal notes.
- Preserve the researched buyer identity, requirements and supplier evidence in the run's output. Keeping the prepared case private must not hide the sources actually retrieved during the demonstration.
- Freeze the evidence ranking before resolving company identities to connected demo accounts. Show a stronger unregistered candidate as an external lead if that is what the evidence supports.
- Connect both demo participants before the stage, but do not use their registration to generate the public-evidence shortlist.
- Preserve audit history while starting each discovery run with no previous candidate/evidence memory. Fresh contexts do not justify deleting authoritative orders, credentials or provider records.

## Acceptance, not a guaranteed success script

Run repeated cold-start rehearsals before the demo, inspect discovery reliability and elapsed time, and retain a backup whose sources are independently accessible. Live source outages can still happen. Return an honest bounded failure rather than silently replaying a saved success.

Exercise at least one changed constraint that must cause refusal. Automated simulated clients are useful, but are not evidence that a named Grok/Instinct product can authenticate, negotiate and report outcomes. Verify the actual clients separately once the integrated backend is available.

No quote, stock, delivery commitment, certification or authority to represent a real organization may be invented. Commercial demo declarations stay distinct from public facts. The [retrieval runbook](demo-runbook.md) contains only generic instructions, not prepared case identities.
